ML & Privacy Module: Features, Technology Stack & System Design

The definitive technical blueprint for the on-device privacy firewall. Transforms raw DOM and screenshot data into a privacy-safe, semantically useful context for the server-side AI agent. Raw PII and session anonymization mappings strictly remain local to the browser.
🛡️ Local Privacy Firewall 🔍 PaddleOCR.js / PP-OCRv5 👁️ YOLO26n ONNX 🧠 BERT-base NER ⚡ Web Worker & WebGPU 🔒 Zero Server PII Leakage
⚠️ Non-Negotiable Security Property
The remote server agent receives enough semantic information to perform autonomous browser reasoning (roles, visible non-sensitive labels, normalized bounding boxes, anonymous session tags), but it must NEVER receive the actual sensitive value or the browser-local mapping that could recover it. All sanitization, OCR, visual masking, and token generation execute 100% locally in the client environment.
🛡️

1. Scope of the ML & Privacy Module

The ML & Privacy module acts as a local client-side privacy firewall. It sits directly between the webpage execution environment and the remote AI agent. It completely owns perception, PII detection, privacy fusion, anonymization, visual/text redaction, session identity management, and sanitized-context delivery.

3. Feature 1 — DOM Analyzer

The DOM analyzer serves as the first-response privacy detector. HTML source code often provides deterministic, explicit signals identifying sensitive fields even when visual rendering is obfuscated or ambiguous.

Semantic HTML Inspection Pipeline Zero-Inference First Pass
Extracts native semantic signals directly from HTML input attributes, ARIA accessibility trees, and surrounding DOM labels before visual models run.
HTML Source → Deterministic Detection Mapping HTML → JSON

/* Output Normalized Detection Objects */
[
  {
    "type": "PASSWORD",
    "confidence": 0.99,
    "source": "DOM",

  • Attribute Heuristics: Deep inspection of type, name, id, placeholder, aria-label, autocomplete (e.g. cc-number, new-password, email, tel).
  • Coordinate Mapping: Extracts precise viewport pixel bounding boxes via getBoundingClientRect() with scroll-offset normalization.
  • Visibility Filtering: Ignores nodes with display: none, visibility: hidden, opacity: 0, or dimensions 0x0 to eliminate false detections from hidden tracking pixels.
  • Dynamic SPA Support: Uses a debounced MutationObserver to continuously re-evaluate DOM changes on React/Vue/Angular single-page apps without performance penalties.
  • Normalized Output: Emits unified Detection objects to the Privacy Engine for subsequent fusion.

5. Feature 3 — YOLO26n Privacy Detector

Certain privacy-critical objects are completely opaque to DOM inspection and OCR text parsing (e.g., photo portraits, QR codes, government card emblems, physical signatures). YOLO26n provides ultra-fast visual object detection to mask these visual entities.

Visual Object Classes & Inference Pipeline ONNX Runtime Web
Trained on privacy-specific datasets with quantized FP16/INT8 execution on WebGPU.
CLASS 01 · BIOMETRIC
FACE
Human portrait photos on user profiles, ID cards, video call previews, and uploaded document thumbnails.
CLASS 02 · IDENTITY
ID_CARD / PASSPORT
Physical government IDs, Aadhaar cards, passport bio pages, and employee badges displayed on screen.
CLASS 03 · FINANCIAL
CREDIT_CARD
Payment cards showing card numbers, expiration dates, logos (Visa/Mastercard/RuPay), and security chips.
CLASS 04 · AUTHENTICATION
SIGNATURE
Handwritten cursive signatures on contracts, official letters, checks, and application forms.
CLASS 05 · MACHINE CODES
QR_CODE / BARCODE
UPI payment QR codes, 2D Aadhaar secure QRs, document barcodes, and boarding pass strips.
CLASS 06 · LICENSING
DRIVER_LICENSE
State driving permits displaying license numbers, driver biometric photos, and home addresses.
  • Quantization Strategy: Starts with an FP32 browser baseline, benchmarked down to FP16 and INT8 for WebGPU/WASM to achieve <40ms inference latency.
  • Conservative Padding: Applies automatic 15–20% safety boundary expansion around high-risk bounding boxes to ensure anti-aliased edges and shadows do not leak sensitive pixels.
  • Detection Schema: Returns class label, normalized bounding coordinates [ymin, xmin, ymax, xmax], detection confidence, and model source identifier.

7. Feature 5 — Layered PII Detection

A single detection modality always suffers from blindspots. PRATYAKSHA enforces a 3-tier layered defense that pools evidence from DOM semantics, algorithmic regex validators, and deep learning NER models.

Detection Layer Target Entity Types Validation Mechanism Confidence Weight
Layer 1: DOM Semantic Rules PASSWORD, CREDENTIALS, PAYMENT_FIELDS, EMAIL, PHONE, OTP Input types, autocomplete attributes, label association, ARIA roles 0.95 – 0.99
Layer 2: Regex & Algorithmic EMAIL, PHONE (+91), PAN, AADHAAR, CREDIT_CARD, IP/URL, GSTIN Verhoeff checksum (Aadhaar), Luhn algorithm (Cards), Modulo-36 (PAN/GSTIN), RFC-5322 (Email) 0.999 (Checksum verified)
Layer 3: BERT-base NER PERSON, LOCATION, ORGANIZATION, Contextual titles & roles Contextual subword token embeddings & classification heads 0.85 – 0.98
✅
Evidence Combination Rule If an entity is detected by multiple layers (e.g. DOM marks an input as type="email" AND regex matches user@isro.gov.in), the Entity Resolver merges the detections, assigns maximum confidence (0.999), and flags the entity for immediate sanitization.

8. Feature 6 — Entity Resolver & Privacy Fusion

Because the webpage is analyzed simultaneously by DOM parsers, OCR engines, YOLO visual detectors, and BERT NER models, the same sensitive data point will produce multiple overlapping detections. The Entity Resolver fuses these detections into a unified spatial entity.

Spatial & Semantic Fusion Algorithm Intersection-over-Union (IoU) 
Incoming Detections for the same screen coordinate:
┌────────────────────────────────────────────────────────────────────────┐
│ DOM Engine:  type = EMAIL,  bbox = [100, 200, 350, 235], conf = 0.95   │
│ OCR Engine:  text = "john@isro.gov.in", bbox = [105, 202, 345, 233]   │
│ NER Engine:  type = NONE                                               │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                         IoU Overlap Calculation:
                         Area(DOM ∩ OCR) / Area(DOM ∪ OCR) = 0.91 > 0.50
                                    │
                                    ▼
FUSED ENTITY CREATED:
{
  "entity_id": "ent_94a2b1",
  "type": "EMAIL",
  "text": "john@isro.gov.in",
  "bbox": [100, 200, 350, 235],
  "sources": ["DOM", "OCR"],
  "confidence": 0.995,
  "action": "SANITIZE_AND_REDACT"
}
  • Geometric Overlap Threshold: Detections with an Intersection-over-Union (IoU) ≥ 0.45 or text-containment ratio > 0.8 are merged into a single parent entity.
  • Type Compatibility Matrix: Reconciles conflicting classifications (e.g. if YOLO detects CREDIT_CARD and OCR finds a 16-digit number, the unified entity is set to CREDIT_CARD with card number metadata).
  • Confidence Boosting: Multi-source agreement increases overall confidence, eliminating false positive alerts while reinforcing true positive masking.

9. Feature 7 — Session Manager (Stable Identity)

Autonomous AI agents require cross-turn identity stability. If a user's name is replaced with [PERSON_A71C] on Step 1, the AI agent must see that exact same identifier on Step 5 when confirming an action. The Session Manager guarantees stable, deterministic pseudonymization for the duration of a workflow session.

Cryptographic Pseudonym Mapping In-Memory Isolation
Local Browser Mapping vs. Server Egress View JavaScript In-Memory Store 
/* 🔒 LOCAL BROWSER IN-MEMORY VAULT (NEVER TRANSMITTED) */
Map(3) {
  "PERSON:John Smith"        → "[PERSON_A71C]",
  "EMAIL:john@isro.gov.in"   → "[EMAIL_92F4]",
  "PHONE:+919876543210"      → "[PHONE_C821]"
}

/* 🌐 WHAT THE REMOTE SERVER AI AGENT SEES: */
{
  "task_context": "Reviewing application for [PERSON_A71C]...",
  "email_target": "[EMAIL_92F4]",
  "contact": "[PHONE_C821]"
}
/* The remote agent reasons perfectly, but CANNOT identify the human! */
  • Cryptographic Unpredictability: Pseudonyms are generated using crypto.getRandomValues() (e.g. [PERSON_<4-hex>]) to prevent statistical re-identification or hash-cracking.
  • Pre-Lookup Normalization: Values are trimmed, lowercased, and canonicalized (e.g. +91 98765-43210 normalized to +919876543210) prior to map lookups to prevent token fragmentation.
  • Strict Non-Reuse: A generated token is bound exclusively to its corresponding real value during the session. No two values will ever share a token.
  • Ephemeral Lifetime: Stored purely in transient RAM. Flushed immediately upon session reset, tab navigation, or workflow completion.
  • Zero Logging Rule: Raw values and mapping dictionaries are strictly prohibited from browser console logs, telemetry payloads, or persistent disk storage.

10. Feature 8 — Semantic Anonymizer

The Semantic Anonymizer replaces sensitive values while preserving grammar, layout, and semantic intent. If all text were blindly redacted or deleted, the AI agent would lose the context needed to navigate the webpage.

Surgical Text Span Rewriting Context Preservation
Original Text (Sensitive Data) Sanitized Output (Safe for AI Reasoning) Reasoning Utility Retained
Welcome John Smith Welcome [PERSON_A71C] Agent knows user is logged in; identifies user element.
Email: john.smith@isro.gov.in Email: [EMAIL_92F4] Agent knows field contains an email; can verify formatting.
Phone: +91 98765 43210 Phone: [PHONE_C821] Agent knows phone is present; can trigger SMS verification.
PAN: ABCDE1234F PAN: [PAN_B301] Agent verifies PAN field is populated and can submit form.
  • Span-Level Granularity: Replaces only the exact character offset of the sensitive token, leaving surrounding labels, navigation headers, button titles, and helper text intact.
  • Syntactic Integrity: Retains punctuation, delimiters, and HTML structure so language model comprehension is unhindered.

11. Feature 9 — Visual Redactor

Before the captured viewport screenshot is serialized for transmission to the server VLM, the Visual Redactor paints irreversible masks over all sensitive coordinates directly on an offscreen HTML5 canvas.

Masking Strategy by Entity Type Pixel-Level Sanitization
TECHNIQUE 01
FACE REDACTION
Heavy Gaussian blur (radius ≥ 25px) or pixelated mosaic blocks with a solid charcoal border overlay.
TECHNIQUE 02
SECRET / PASSWORD
100% opaque solid black/charcoal rectangle wipe completely destroying underlying pixel values.
TECHNIQUE 03
ID / CARD / SIGNATURE
Opaque charcoal mask with mandatory 15% safety padding to prevent edge character bleeding.
TECHNIQUE 04
QR / BARCODE
Complete spatial rectangular wipe covering the entire optical code region plus quiet zone margin.
🚫
Zero Reversibility Guarantee Redaction is performed using native Canvas 2D fillRect() and destructive pixel manipulation before creating the final WebP/JPEG blob. There are no client-side "layers" that can be hidden or removed by an attacker—the sensitive pixels are permanently destroyed.

14. Feature 12 — Web Worker Performance Isolation

Executing machine learning models, OCR detection, and image masking directly on the webpage's main thread would cause severe frame drops and freeze user interactions. PRATYAKSHA enforces 100% off-thread execution inside dedicated Web Workers.

Thread Architecture & Message Protocol Zero Main-Thread Jank 
MAIN BROWSER THREAD (Content Script)
  │
  ├── 1. Captures DOM snapshot (15ms)
  ├── 2. Grabs viewport ImageBitmap (10ms)
  ├── 3. Sends transferable ImageBitmap → postMessage()
  │
  ▼
DEDICATED INFERENCE WEB WORKER (Off-Thread)
  │
  ├── 4. PaddleOCR.js executes in parallel (WASM/WebGPU)
  ├── 5. YOLO26n runs visual detection (WebGPU)
  ├── 6. BERT-base NER extracts contextual entities
  ├── 7. PrivacyEngine fuses entities & assigns pseudonyms
  ├── 8. Visual Redactor applies masks to OffscreenCanvas
  │
  ▼
TRANSFER BACK (postMessage)
  │
  └── Sanitized Context → Extension Background Script → Remote AI Agent
  • Zero UI Freezing: The host webpage maintains a smooth 60 FPS while heavy multi-model ML pipelines execute concurrently.
  • Zero-Copy Transferable Objects: Uses ImageBitmap and ArrayBuffer transfer semantics to eliminate memory copying overhead between threads.
  • Worker Memory Sandboxing: Crash isolation—if an ML model experiences an out-of-memory exception, the Web Worker terminates without crashing the user's browser tab.

17. Internal Component Design

The PrivacyEngine is architected with clean, decoupled interfaces to allow individual models to be upgraded, replaced, or unit-tested in complete isolation.

Object-Oriented Component Hierarchy Modular Architecture 
PrivacyEngine
├── DOMDetector          [Inspects HTML elements, attributes, ARIA, and bboxes]
├── OCRDetector          [Runs PaddleOCR.js, extracts text strings and polygons]
├── VisionDetector       [Runs YOLO26n ONNX model, detects visual privacy objects]
├── PIIClassifier        [Orchestrates multi-layer PII rule evaluation]
│   ├── DOMRules         [Evaluates type="password", autocomplete, name heuristics]
│   ├── RegexRules       [Runs Verhoeff, Luhn, PAN, Email, and Phone validators]
│   └── BERTNER          [Runs BERT-base contextual entity recognition]
├── EntityResolver       [Performs IoU spatial fusion, deduplication, and confidence weighting]
├── SessionManager       [Manages crypto.getRandomValues token dictionaries and expiry]
├── TextRedactor         [Rewrites textual character spans with assigned tokens]
├── VisualRedactor       [Applies destructive blur and opaque fills on Canvas/ImageBitmap]
└── ContextBuilder       [Serializes sanitized JSON wire schema and encodes final screenshot]

  • Mock-Ready Unit Testing: Detectors can be mocked with synthetic inputs to test downstream fusion and redaction logic without loading heavy ONNX runtimes.

18. 10-Step Operational Execution Loop

The autonomous agent executes a cyclic 10-step perception-privacy-action loop for every user interaction.

1
OBSERVE Input Step

Content script queries live DOM tree and captures the current viewport as an ImageBitmap.

2
DETECT Multi-Model

Web Worker runs parallel perception: DOM Analyzer + PaddleOCR + YOLO26n + BERT-base NER + Regex Rules.

3
FUSE Spatial Logic

Entity Resolver reconciles overlapping bounding boxes and classifications via IoU and confidence fusion.

4
IDENTIFY Cryptographic Token

Session Manager normalizes values and maps each unique entity to a stable anonymous session pseudonym.

5
PROTECT Redaction

Semantic Anonymizer rewrites sensitive text spans; Visual Redactor permanently masks canvas pixels.

6
VERIFY Privacy Gate

Final Privacy Gate performs pre-flight audit: fails closed if any unmasked entity or raw PII is detected.

7
SEND Network Egress

Transmits sanitized context payload (JSON elements + redacted screenshot WebP) to the remote AI agent.

8
REASON Server AI

Server-side VLM/LLM analyzes the sanitized scene graph and plans the next optimal UI action.

9
ACT Browser Execution

Browser extension receives structured action (CLICK, TYPE, SCROLL) and executes it on the local DOM.

10
OBSERVE AGAIN Loop Closure

Page state updates in response to the action; pipeline cycles back to Step 1 for the next turn.
