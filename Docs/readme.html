Executive Summary & Overview

Commercial browser AI agents (MultiOn, Adept, Operator, Computer Use) require sending high-resolution, unredacted screen captures and full DOM dumps to third-party cloud LLM APIs. In national space missions, defense, and sovereign public administration, this represents an intolerable data breach risk.

⚠️
The ISRO Core Mandate
Sensitive citizen identity (Aadhaar, PAN, Voter ID), defense credentials, session tokens, and classified telemetry must be sanitized on-device inside the browser sandbox before any network byte is emitted. Only anonymized, mathematically sanitized visual context may leave the perimeter.

PRATYAKSHA solves this through a lightweight (~20MB total footprint) on-device neural vision stack compiled to WebGPU via ONNX Runtime Web. It runs client-side in an isolated Offscreen Document, pairing deep neural text/face detection with algorithmic Indian PII validators (Verhoeff checksum for Aadhaar, modulo-36 for GSTIN). The server VLM plans actions using synthetic placeholders (e.g. ⟨AADHAAR_01⟩), and the local agent executes them seamlessly while never exposing raw PII.

Problem Statement Analysis (ISRO SAC PS-26171)

The official problem statement issued by ISRO Space Applications Centre (SAC) specifies:

📖
Official Challenge Excerpt
"Development of an on-device visual perception pipeline for light-weight browser agents. The solution must extract visual context from web pages, detect and redact sensitive personally identifiable information (PII) before transmission, and support autonomous multi-step workflow execution guided by a central Vision-Language Model."

❌ Traditional Agent Failure

Takes raw screenshots & transmits to OpenAI / Anthropic / Google cloud endpoints. Immediate violation of DPDP Act 2023, ISRO Security Manual, and CERT-In national cyber guidelines.

✅ PRATYAKSHA Solution

Sanitizes both DOM trees and pixel buffers inside WebGPU Offscreen worker. Swaps sensitive data with structured semantic tokens. Zero plaintext sensitive data ever crosses the network boundary.

⚖️

System Architecture at a Glance

The 5-step perception-action pipeline decouples local perception and sanitization from central multi-modal reasoning.

PRATYAKSHA END-TO-END PIPELINE TOPOLOGY MV3 + WebGPU + Private VLM 
Browser Extension (Chrome MV3 / Firefox WebExtension)
│
├── 1. PERCEIVE    → chrome.tabs.captureVisibleTab() + DOM Scene Tree Extractor
├── 2. SANITIZE    → Offscreen WebGPU Pipeline (Ultra-Light-Face + DBNet + CRNN)
│                     ┌─ Verhoeff (Aadhaar), Modulo-36 (GSTIN), IFSC Dictionary
│                     └─ Reversible Pseudonym Vault (Local In-Memory Map)
├── 3. TRANSMIT    → Only Sanitized Canvas + Tokenized Scene Graph → HTTPS/WSS
│
└──→ SERVER (ISRO Intranet / Self-Hosted Enterprise GPU Node)
         Qwen2.5-VL-7B-Instruct (Open-Weights, 100% Offline Deployable)
         Receives: Sanitized pixels + semantic tokens (⟨AADHAAR_01⟩, ⟨PAN_01⟩)
         Returns:  Structured JSON Action Plan with token targets
┌──← CLIENT RETURN
│
├── 4. REHYDRATE   → Client Rehydration Vault swaps tokens back to real values LOCALLY
└── 5. EXECUTE     → Content Script synthesizes events (click, type, scroll) in DOM

Our 5 Core Technical Innovations

🔐
Reversible Pseudonym Vault
Instead of destructive black-box redaction, PRATYAKSHA generates typed tokens like ⟨AADHAAR_01⟩ and preserves their bounding box geometry. The server VLM can reference these tokens in actions, and the client securely rehydrates the real value into form fields right before dispatching keyboard events.
🛡️
Fail-Closed Dual-Channel Fusion
Combines structural DOM priors with neural pixel-level DBNet text detection. If DOM analysis misses a canvas signature, scanned PDF, or shadow DOM field, the WebGPU vision channel catches it. If either channel flags sensitive data, redaction is triggered immediately.
🇮🇳
Sovereign Indian PII Stack
Hardened against Indian governmental formats: Verhoeff algorithm for 12-digit Aadhaar validation (eliminates false positives from serial numbers), PAN structure validator, GSTIN modulo-36 checksum, RBI IFSC routing table, and multilingual Devanagari OCR models.
🧾
Cryptographic Egress Ledger
Every single frame and JSON payload transmitted to the server is hashed with SHA-256 and appended to a tamper-proof in-memory Merkle chain. Users and security auditors can open the Side Panel HUD to verify the exact split-screen diff of what left the browser.
